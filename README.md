# 支出の余白

支出を記録して暮らしに余白をつくる、スマートフォン優先の支出管理Webアプリです。サーバー・外部API・クラウドDBは不要です。

## 主な機能

- アプリ起動 → パスワード解除 → すぐに支出を記録
- 金額・使い道→カテゴリーの順に入力できる記録画面、日付、電卓、予定／予定外の区分、5段階評価
- カテゴリー別月間予算の設定と**月間予算の合計・使用額・残額**表示。編集中の予算にも即時反映
- カテゴリーの新規登録時、食べ物・暮らし・交通・買い物などの分類から多数の絵文字アイコンを選択可能
- 日・週・月の支出合計、月間カテゴリー降順集計、月ごとの記録一覧
- 日付ごとの金額と予定外支出がわかるカレンダー
- 円グラフ・横棒グラフ・折れ線グラフ、最大支出、満足度別・予定／予定外の集計
- 週／月／年の定期支出を設定し、アプリ起動時に到来した支出を自動登録
- CSVダウンロード、暗号化JSONバックアップ／復元、パスワード変更
- GitHub Pagesに公開できる静的サイト。HTTPS下ではオフライン用のキャッシュも利用可能

## GitHub Pages 公開手順

1. GitHubで新規リポジトリを作成します（例：`shishutsu-no-yohaku`）。
2. このフォルダに入っているファイルをすべて（`.nojekyll` を含む）リポジトリの**ルート**にアップロードします。ZIPのままではなく、解凍してアップロードします。
3. リポジトリの **Settings → Pages → Build and deployment → Source** を **Deploy from a branch** にします。
4. **Branch: `main` / `/(root)`** を選んで **Save** を押します。
5. 表示された公開URLを開き、数字4桁以上のパスワードを設定してください。

GitHub Pages公開によりWebアプリの**ソースコードは公開**されますが、家計簿の記録そのものはリポジトリへアップロードされず、ブラウザ内で暗号化して保存されます。支出の機密情報をソースコードやGitHubのコミットへ書き込まないでください。

## 安全性とバックアップ

- 入力した支出・予算・カテゴリー等は `localStorage` へ **AES-256-GCM** で暗号化して保存。鍵はパスワードから PBKDF2-SHA-256（31万回）で導出します。
- パスワード自体は保存しません。忘れた場合は記録を復号できません。覚えられるだけでなく、4桁は総当たりや推測に弱いため、6〜8桁以上の数字を推奨します。以前設定した英数字のパスワードは引き続き解除に利用でき、設定画面から数字パスワードに変更できます。
- サーバー上にはデータがありません。**ブラウザを変える、スマートフォンを交換する、サイトデータを削除する、プライベートブラウズ終了**等により記録は失われることがあります。設定画面の「暗号化バックアップ」を定期的に取得してください。
- 別端末への移行は、元の端末で暗号化バックアップJSONを書き出し、新端末で「バックアップを復元」して同じパスワードで解錠してください。
- CSVは**暗号化されていません**。保存・共有先にご注意ください。
- セキュリティは端末とブラウザの安全性に依存します。悪意のあるブラウザ拡張や不正なスクリプト、端末自体への侵入からの完全な保護を保証するものではありません。
- 他の家計簿・口座との自動同期は行いません。定期支出は**アプリが開かれたとき**に、支払予定日までの分を登録します。実際の請求を確認する機能ではありません。

## 利用技術

HTML / CSS / JavaScript（外部ライブラリなし）、Web Crypto API、localStorage、Service Worker、PWA。

## 更新時の注意

静的ファイルの更新をGitHub Pagesへ反映しても、利用者の暗号化済み記録は通常そのまま残ります。ただし、閲覧するGitHub Pagesの**ドメインやパスを変更**すると保存領域が異なる場合があります。URLを変更する前に暗号化バックアップを必ず取得してください。

## 今回のアップデート

1. 支出登録画面の入力順を **①金額・使い道・記録日 → ②カテゴリー** に変更。予定／予定外、5段階評価はその後にあります。
2. 設定の月間予算に、設定済みカテゴリーの**予算合計・今月の対象支出・残額**を追加。予算額を入力中にも数値が更新されます。予算未設定カテゴリーの支出は残額の計算に含みません。
3. カテゴリーを新規登録するとき、種類別の絵文字一覧からアイコンを選べます。追加したカテゴリーのアイコンは既存の記録と同様に暗号化データに保存されます。
4. Service Workerのキャッシュ識別子を更新し、既存のGitHub Pagesでも更新が反映されやすいようにしました。

**既存データについて：** 以前のパスワードや記録、カテゴリー、予算などはそのまま利用する設計です。公開ファイルの更新前に「設定」から暗号化バックアップを取ることを推奨します。暗号化データ保存キーおよび形式は変更していません。
